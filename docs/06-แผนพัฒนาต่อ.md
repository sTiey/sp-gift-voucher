# 06 · แผนพัฒนาต่อ

ระบบนี้ตั้งใจให้ **ต่อยอดได้เรื่อย ๆ** ไม่ใช่ของที่เสร็จแล้วจบ
หน้านี้คือรายการสิ่งที่ทำต่อได้ เรียงตาม "คุ้มที่สุดก่อน"

---

## สถานะตอนนี้

| ส่วน | สถานะ |
|---|---|
| โครงข้อมูลคูปอง | ✅ ครบ ใช้งานได้ |
| ตรรกะการใช้สิทธิ์ + คิดส่วนลด | ✅ ครบ มีเทสต์ 92 ข้อ + สถานการณ์จริง 49 อัน |
| ระบบดีไซน์ (โทเคน · 3 ธีม · 3 รูปแบบใบ) | ✅ ครบ |
| QR สร้างเอง | ✅ ตรงมาตรฐาน 217/217 เคส · ⚠️ ยังไม่เคยสแกนด้วยมือถือจริง |
| หน้าจอใช้งาน 5 หน้า | ✅ เดินได้จริงในเบราว์เซอร์ |
| ทดสอบบนมือถือจริง | ❌ ยังไม่เคยทำ |
| หลังบ้านจริง | ❌ ยังไม่มี (เก็บในเบราว์เซอร์) |
| ความปลอดภัยระดับใช้เงินจริง | ❌ ยังไม่ถึง |

## เฟส 1 · ทำให้พร้อมใช้จริง

สิ่งที่ต้องมี ก่อนให้ลูกค้าคนแรกแตะ

| # | งาน | ทำไม | ประมาณ |
|---|---|---|---|
| 1.1 | **ให้ไท้เปิดบนมือถือจริงดู** | บั๊กหน้าจอมือถือที่สำคัญที่สุด คอมมองไม่เห็นเด็ดขาด | ครึ่งวัน |
| 1.2 | **ลองสแกน QR ด้วยกล้องมือถือ** | ตรวจแล้วว่าตรงมาตรฐาน แต่ยังไม่เคยมีใครยกมือถือขึ้นส่อง | 10 นาที |
| 1.3 | **หลังบ้านจริง** (API + ฐานข้อมูล) | หน้าเว็บตัดสินเองอยู่ตอนนี้ = แก้ได้ = โกงได้ | 3-5 วัน |
| 1.4 | **ตัดสิทธิ์แบบกันซ้ำ** ที่ฐานข้อมูล | ลูกค้ากดสองครั้งพร้อมกัน = ใช้ได้สองรอบ | รวมใน 1.3 |
| 1.5 | **รหัสยืนยันสดคิดที่เซิร์ฟเวอร์** | ตอนนี้ความลับอยู่ในหน้าเว็บ | ครึ่งวัน |
| 1.6 | **จำกัดจำนวนครั้งที่ยิงตรวจรหัส** | กันคนไล่สุ่มรหัส | ครึ่งวัน |

## เฟส 2 · ทำให้ใช้งานสะดวกขึ้น

| # | งาน | ได้อะไร |
|---|---|---|
| 2.1 | **สแกน QR ด้วยกล้องในหน้าพนักงาน** | พนักงานไม่ต้องพิมพ์รหัสเอง เร็วขึ้นมากและไม่พิมพ์ผิด |

## ของที่ทำง่ายมาก (เก็บตอนมีเวลาว่าง)

- เพิ่มธีมที่ 4 — ก๊อปไฟล์สีไฟล์เดียว
- ภาษาอังกฤษ — ก๊อป `strings.th.js` ไปแปล
- ใส่โลโก้บริษัทบนใบ — มี `brand.logoUrl` รออยู่แล้ว
- ภาพประกอบบนใบ — มี `design.artUrl` รออยู่แล้ว แต่ยังไม่ได้ทำส่วนแสดงผล
- พิมพ์ใบคูปองลงกระดาษ (เผื่อบางงานยังต้องใช้) — เขียน CSS สำหรับพิมพ์เพิ่ม

## สิ่งที่ตัดสินใจ "ไม่ทำ" และเหตุผล

| ไม่ทำ | เพราะ |
|---|---|
| ใช้ React / Vue / เฟรมเวิร์กใด ๆ | ระบบนี้ต้องเอาไปแปะในเว็บอะไรก็ได้ ถ้าผูกกับเฟรมเวิร์กจะแปะไม่ได้ |
| ใช้ Shadow DOM | จะปรับแต่งหน้าตายากขึ้นโดยไม่ได้อะไรกลับมา |
| ดึงฟอนต์จาก Google Fonts | โหลดไม่ได้แล้วหน้าตาเพี้ยนเงียบ ๆ + ส่ง IP ลูกค้าออกไปข้างนอก |
| ใช้ไลบรารีสร้าง QR | เขียนเองแล้วไม่ต้องส่งรหัสลูกค้าออกนอกเครื่อง และไม่มี dependency ให้ตามอัปเดต |
| เก็บสถานะ "หมดอายุ" ลงฐานข้อมูล | ต้องมีงานเบื้องหลังไล่อัปเดตทุกใบทุกวัน พังง่ายและช้า |
| แผงเลื่อนขึ้นจากล่างจอตอนใช้สิทธิ์ | `position: fixed` มีปัญหากับ Safari บน iPhone และวิธีปัจจุบันใช้ง่ายกว่า |

## หมายเหตุถึงคนที่มาทำต่อ

1. **แก้ `schema.js` ก่อนเสมอ** ถ้าจะเพิ่มความสามารถที่ต้องเก็บข้อมูลใหม่
2. **รัน `node tools/selftest.mjs` ทุกครั้งก่อนคิดว่าเสร็จ**
   — เพิ่มความสามารถใหม่ ให้เพิ่ม "สถานการณ์" ใน `tests/scenarios.js` ด้วย
   ไฟล์นั้นเป็นทั้งเทสต์อัตโนมัติและหน้าที่คนเปิดดูเองได้ (`/demo/scenarios.html`)
3. **หน้าตาต้องเปิดดูด้วยตา** เทสต์ไม่ช่วยเรื่องนี้ — ใช้ `node tools/shot.mjs <url> <out.png>`
   แคปหน้าจอออกมาดูได้
4. **ห้ามเขียนค่าสี/ขนาดดิบในไฟล์ CSS** ให้ไปเพิ่มโทเคนแทน
5. **ห้ามพิมพ์ข้อความไทยลงในไฟล์ UI ตรง ๆ** ให้ไปเพิ่มใน `strings.th.js`
6. อ่าน [05 ความปลอดภัยและกับดัก](05-ความปลอดภัยและกับดัก.md) หัวข้อ 6 ก่อน
   — เป็นรายการบั๊กที่เคยเจอแล้วและ **ไม่มี error ให้เห็นสักตัว**
