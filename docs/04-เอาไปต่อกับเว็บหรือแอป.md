# 04 · เอาไปต่อกับเว็บหรือแอป

ตอนนี้ระบบเดินได้ในเบราว์เซอร์อย่างเดียว หน้านี้บอกวิธีเอาไปต่อกับของจริง

---

## 1. เอาแค่หน้าตาไปใช้ (ง่ายสุด)

```html
<link rel="stylesheet" href="voucherkit/src/styles/fonts.css">
<link rel="stylesheet" href="voucherkit/src/tokens/tokens.css">
<link rel="stylesheet" href="voucherkit/src/tokens/skin-steel.css">
<link rel="stylesheet" href="voucherkit/src/styles/base.css">
<link rel="stylesheet" href="voucherkit/src/styles/voucher.css">

<gift-voucher layout="slab"></gift-voucher>

<script type="module">
  import { createVoucher } from './voucherkit/src/index.js';
  document.querySelector('gift-voucher').voucher = createVoucher({
    code: 'SPE-7K4M-92XH', kind: 'percent', value: 15,
    title: 'ส่วนลดพาร์ทเนอร์', brand: { name: 'SP Empire' },
  });
</script>
```

**ใน React / Vue** — เรียกฟังก์ชันวาดเอา HTML ไปใส่เอง

```jsx
import { voucherCardHtml } from 'voucherkit/src/index.js';

function VoucherCard({ voucher }) {
  return <div dangerouslySetInnerHTML={{ __html: voucherCardHtml(voucher) }} />;
}
```

**ฝั่งเซิร์ฟเวอร์** (อีเมล · หน้าที่ render จากหลังบ้าน) ก็เรียกฟังก์ชันเดียวกันได้
เพราะมันคืนสตริงเฉย ๆ ไม่แตะ DOM

## 2. ต่อกับหลังบ้านจริง

ทั้งระบบคุยกับที่เก็บข้อมูลผ่านสัญญา 5 เมธอด เขียน Adapter ตัวใหม่ตัวเดียวจบ

```js
class MyStore {
  async list()        { /* คูปองทั้งหมด */ }
  async get(code)     { /* คูปอง 1 ใบ หรือ null */ }
  async put(voucher)  { /* เขียนทับ/เพิ่ม */ }
  async remove(code)  { /* ลบ */ }
  async clear()       { /* ล้างทั้งหมด */ }
}

const svc = new VoucherService(new MyStore());
```

มี `HttpStore` ให้แล้วถ้า API หน้าตาเป็น REST มาตรฐาน:

```js
import { VoucherService, HttpStore } from 'voucherkit/src/index.js';
const svc = new VoucherService(new HttpStore('https://api.บริษัท.com/v1'));
```

### API ที่ควรมี

| เมธอด | ทาง | ทำอะไร |
|---|---|---|
| `GET` | `/vouchers/:code` | ดึงคูปอง 1 ใบ |
| `POST` | `/vouchers/:code/check` | **ตรวจ** ว่าใช้ได้ไหม (ไม่เปลี่ยนอะไร) |
| `POST` | `/vouchers/:code/reserve` | **จอง** ระหว่างลูกค้ากำลังจ่ายเงิน |
| `POST` | `/vouchers/:code/redeem` | **ตัดสิทธิ์** (ต้องกันซ้ำแบบ atomic) |
| `POST` | `/vouchers/:code/release` | ปล่อยการจอง |
| `POST` | `/campaigns/:id/issue` | ปั๊มคูปองหลายใบ |
| `POST` | `/vouchers/:code/void` | ยกเลิก |

`check` / `redeem` รับ **บริบท** (ยอด · ลูกค้า · ช่องทาง · สาขา) แล้วคืนผลหน้าตา
เหมือน `evaluate()` เป๊ะ — ดู [02 โครงสร้างข้อมูล](02-โครงสร้างข้อมูล.md) หัวข้อ "บริบทตอนใช้สิทธิ์"

## 3. จุดที่ต้องระวัง (สำคัญกว่าโค้ด)

### 3.1 หลังบ้านต้องคิดเลขด้วยโค้ดชุดเดียวกัน

ถ้าหน้าเว็บบอกลูกค้าว่า "ลด 2,000" แล้วหลังบ้านคิดได้ 1,800 ลูกค้าจะโกรธ

โฟลเดอร์ `src/core/` ทั้งก้อน **ไม่รู้จัก `document` หรือ `window` เลย** ตั้งใจทำมาแบบนี้
เพื่อให้ก๊อปไปวางบน Node.js ฝั่งเซิร์ฟเวอร์แล้วเรียก `evaluate()` ตัวเดียวกันได้เลย

**อย่าเขียนสูตรคิดส่วนลดขึ้นใหม่ที่หลังบ้าน** — วันหนึ่งสองฝั่งจะไม่ตรงกันแน่นอน

### 3.2 การตัดสิทธิ์ต้องกันซ้ำที่ฐานข้อมูล

ลูกค้ากดสองครั้งพร้อมกัน หรือเปิดสองแท็บ = ยิงเข้ามาพร้อมกัน 2 คำสั่ง

หลังบ้านต้องทำให้ "ตรวจว่ายังใช้ได้ + เพิ่มจำนวนที่ใช้" เกิดใน**ก้าวเดียว** เช่น

```sql
UPDATE vouchers SET used = used + 1
WHERE code = ? AND state = 'issued'
  AND (total_limit IS NULL OR used < total_limit)
```

แล้วเช็คว่ามีแถวถูกแก้จริงไหม ถ้า 0 แถว = มีคนตัดไปก่อนแล้ว

> ⚠️ `VoucherService.redeem()` ในโปรเจกต์นี้ **ไม่ได้กันเคสนี้** เพราะมันอ่านแล้วค่อยเขียน
> ใช้กับต้นแบบได้ ใช้กับเงินจริงไม่ได้

### 3.3 การจองมีเวลาหมดอายุเสมอ

`reserve()` ล็อกคูปองไว้ 5 นาที ถ้าลูกค้าปิดหน้าเว็บหนีระหว่างจ่ายเงิน
คูปองจะปลดล็อกเองเมื่อเลยเวลา — ระบบไม่ต้องมีงานเบื้องหลังคอยตามเก็บ
เพราะ `deriveStatus()` มองว่าการจองที่เลยเวลาแล้วเท่ากับใช้ได้ตามปกติ

### 3.4 รหัสยืนยันสดต้องคิดที่เซิร์ฟเวอร์

ตอนนี้คิดในเบราว์เซอร์เพื่อให้ตัวอย่างเดินได้ ซึ่งแปลว่าความลับอยู่ในหน้าเว็บ = ปลอมได้
ของจริงต้องย้ายไปคิดด้วย HMAC-SHA256 บนเซิร์ฟเวอร์ → [05 ความปลอดภัย](05-ความปลอดภัยและกับดัก.md)

## 4. ส่งคูปองถึงมือลูกค้า

ลิงก์คูปอง 1 ใบ:

```
https://เว็บบริษัท.com/voucher?c=SPE-7K4M-92XH
```

```js
import { voucherUrl } from 'voucherkit/src/index.js';
voucherUrl('SPE-7K4M-92XH', 'https://เว็บบริษัท.com/voucher');
```

| ช่องทาง | ทำยังไง |
|---|---|
| LINE OA | ส่ง Flex Message แนบลิงก์ · หรือส่งรูปใบคูปองที่ render จากหลังบ้าน |
| อีเมล | ฝังภาพใบ + ปุ่มลิงก์ (อีเมลรัน JavaScript ไม่ได้ ต้อง render เป็นภาพ/HTML นิ่ง) |
| SMS | ส่งแค่รหัส + ลิงก์สั้น |
| ในแอป | เปิดหน้า `wallet` ในแอปเลย ไม่ต้องออกเบราว์เซอร์ |

> **ลิงก์สั้นเข้าไว้** — QR ที่บรรจุข้อความยาวจะละเอียดขึ้นเรื่อย ๆ และสแกนยากขึ้น
> ลิงก์ราว 50-70 ตัวอักษรกำลังดี ระบบรองรับสูงสุด 213 ตัวอักษร

## 5. เพิ่มของใหม่

### เพิ่มชนิดสิทธิ์ใหม่ (เช่น "ผ่อน 0% 6 เดือน")

1. เติมชื่อใน `KINDS` ที่ `src/core/schema.js`
2. เติมคำไทยใน `strings.th.js` หัวข้อ `kind.*`
3. เติมวิธีคิดเงินใน `computeDiscount()` ที่ `rules.js`
4. เติมวิธีแสดงผลใน `valueParts()` ที่ `format.js`
5. เขียนเทสต์ใน `tools/selftest.mjs`

ชุดทดสอบมีข้อที่บังคับว่า **ทุกชนิดสิทธิ์ต้องมีตัวอย่างอย่างน้อย 1 ใบ** ในไฟล์ข้อมูลตัวอย่าง
จะได้ไม่มีหน้าตาแบบไหนที่ไม่เคยมีใครเห็น

### เพิ่มกลุ่มลูกค้าใหม่

เติมใน `SEGMENTS` + `strings.th.js` หัวข้อ `segment.*` — จบ
หน้าแอดมินจะขึ้นตัวเลือกใหม่ให้เอง

### เพิ่มธีมใหม่

→ [03 ระบบดีไซน์](03-ระบบดีไซน์.md) หัวข้อ 3

### เพิ่มภาษา

```js
import { registerLocale, setLocale } from 'voucherkit/src/index.js';
import { EN } from './strings.en.js';   // ก๊อป strings.th.js มาแปล
registerLocale('en', EN);
setLocale('en');
```

## 6. ก่อนปล่อยขึ้นใช้จริง — เช็คลิสต์

- [ ] ย้ายการตัดสินใจไปหลังบ้าน (หน้าเว็บใช้แสดงผลเท่านั้น)
- [ ] ตัดสิทธิ์แบบกันซ้ำได้จริงที่ฐานข้อมูล
- [ ] รหัสยืนยันสดคิดด้วย HMAC บนเซิร์ฟเวอร์
- [ ] จำกัดจำนวนครั้งที่ยิงตรวจรหัสได้ (กันคนไล่สุ่มรหัส)
- [ ] เก็บ log ว่าใครใช้คูปองไหนเมื่อไหร่ที่สาขาอะไร
- [ ] ทดสอบบนมือถือจริง โดยเฉพาะ iPhone
- [ ] ลองสแกน QR ด้วยกล้องมือถือจริง
- [ ] ตั้ง cache ให้ไฟล์ฟอนต์ (ไฟล์ที่ไม่มีวันเปลี่ยนควรตั้ง `immutable`)
