# 02 · โครงสร้างข้อมูล

คูปอง 1 ใบหน้าตายังไง · ทุก field มีค่าเริ่มต้น จะใส่แค่ 2-3 ตัวก็ได้ของครบ

แหล่งความจริงคือ `src/core/schema.js` — **จะเพิ่ม field ใหม่ ต้องเพิ่มที่นั่นก่อนเสมอ**

---

## ตัวอย่างที่สั้นที่สุดที่ใช้งานได้

```js
import { createVoucher } from './src/index.js';

const v = createVoucher({
  code: 'SPE-7K4M-92XH',
  kind: 'percent',
  value: 15,
  title: 'ส่วนลดพาร์ทเนอร์',
});
```

ที่เหลือระบบเติมให้เอง (ใช้ได้ทันที · ไม่มีวันหมด · ใครก็ใช้ได้ · 1 สิทธิ์ · ธีมเหล็ก)

---

## ตารางเต็ม

### สิทธิ์ที่ได้

| field | ชนิด | ค่าเริ่มต้น | อธิบาย |
|---|---|---|---|
| `code` | ข้อความ | `''` | รหัสที่ลูกค้าเห็น เช่น `SPE-7K4M-92XH` |
| `kind` | ข้อความ | `'percent'` | ชนิดสิทธิ์ 5 แบบ (ตารางถัดไป) |
| `value` | ตัวเลข | `0` | ความหมายขึ้นกับ `kind` |
| `currency` | ข้อความ | `'THB'` | เผื่ออนาคตขายต่างประเทศ |

| `kind` | `value` หมายถึง | ตัวอย่างบนใบ |
|---|---|---|
| `percent` | เปอร์เซ็นต์ที่ลด | `15%` |
| `amount` | จำนวนเงินที่ลด | `฿1,500` |
| `fixed_price` | ราคาพิเศษที่ต้องจ่าย | `฿7,900` |
| `free_item` | จำนวนชิ้นที่แถม | `×1` |
| `free_shipping` | ไม่ใช้ | `ส่งฟรี` |

### ข้อความที่พิมพ์บนใบ

| field | ชนิด | อธิบาย |
|---|---|---|
| `title` | ข้อความ | หัวข้อหลักบนใบ |
| `subtitle` | ข้อความ | บรรทัดรอง (ยังไม่ได้ใช้บนการ์ด เก็บไว้ใช้ในอีเมล) |
| `note` | ข้อความ | ข้อความส่วนตัว เช่น "ขอบคุณที่อยู่กับเรามา 3 ปี" |
| `terms` | รายการข้อความ | เงื่อนไขเป็นข้อ ๆ โชว์ในหน้าคูปอง |
| `brand.name` | ข้อความ | ชื่อแบรนด์มุมบนซ้าย |
| `brand.logoUrl` | ข้อความ/null | ใส่แล้วขึ้นโลโก้แทนช่องว่าง |

### เงื่อนไขการใช้ · `conditions`

| field | ค่าเริ่มต้น | อธิบาย |
|---|---|---|
| `minSpend` | `null` | ยอดขั้นต่ำ (บาท) |
| `maxDiscount` | `null` | เพดานส่วนลด — สำคัญมากกับ `percent` |
| `channels` | `[]` | ว่าง = ทุกช่องทาง · เช่น `['web','app','store']` |
| `branches` | `[]` | ว่าง = ทุกสาขา |
| `productScope.include` | `[]` | รหัสสินค้าที่เข้าเงื่อนไข |
| `productScope.categories` | `[]` | หมวดสินค้าที่เข้าเงื่อนไข |
| `productScope.exclude` | `[]` | รหัสสินค้าที่ยกเว้น |
| `combinable` | `false` | ใช้ร่วมกับส่วนลดอื่นได้ไหม |

> **`maxDiscount` คือสิ่งที่ลืมแล้วเจ็บที่สุด**
> ลด 15% ไม่มีเพดาน เจอออร์เดอร์ 800,000 บาท = ลดไป 120,000 บาท

> **`productScope` เปลี่ยนฐานคิดเงิน** — ถ้าตั้งไว้ ระบบจะคิดส่วนลดจาก
> *เฉพาะยอดสินค้าที่เข้าเงื่อนไข* ไม่ใช่ยอดทั้งตะกร้า

### ใครใช้ได้ · `audience`

| field | ค่าเริ่มต้น | อธิบาย |
|---|---|---|
| `segments` | `['public']` | กลุ่มลูกค้า — `public` `partner` `vip` `returning` `new` `staff` |
| `customerId` | `null` | ผูกกับลูกค้าคนเดียว (คนอื่นถือไปก็ใช้ไม่ได้) |
| `customerName` | `null` | ชื่อไว้แสดง |

เพิ่มกลุ่มใหม่: เติมชื่อใน `SEGMENTS` ที่ `schema.js` + เติมคำไทยใน `strings.th.js` หัวข้อ `segment.*`
หน้าแอดมินจะขึ้นตัวเลือกใหม่ให้เอง

### อายุและโควตา

| field | ค่าเริ่มต้น | อธิบาย |
|---|---|---|
| `validFrom` | `null` | `null` = ใช้ได้ทันที · ใส่วันที่ = ก่อนถึงวันจะขึ้น "ยังไม่เริ่ม" |
| `validUntil` | `null` | `null` = ไม่มีวันหมด |
| `limits.perPerson` | `1` | คนหนึ่งใช้ได้กี่ครั้ง |
| `limits.total` | `1` | ใช้ได้กี่ครั้งรวมทุกคน |
| `usage.used` | `0` | ใช้ไปแล้วกี่ครั้ง (ระบบนับให้) |
| `usage.byCustomer` | `{}` | ใครใช้ไปแล้วกี่ครั้ง (ระบบนับให้) |

**`limits.total` ตั้งยังไง**

| ตั้งเป็น | หมายถึง | ใช้กับ |
|---|---|---|
| `1` | ใบเดียวจบ | คูปองส่วนตัว · บัตรกำนัล (ค่าเริ่มต้น) |
| `30` | 30 สิทธิ์ ใครมาก่อนได้ก่อน | โปรจำนวนจำกัด |
| `null` | ไม่จำกัดครั้ง | โค้ดสาธารณะ เช่น `SONGKRAN10` |

> ⚠️ ใช้ `null` ต้องส่ง `customerId` มาด้วยทุกครั้ง ไม่งั้น `perPerson` กันอะไรไม่ได้
> คนเดียวจะใช้ซ้ำได้ไม่จำกัด

### สถานะ

| field | อธิบาย |
|---|---|
| `state` | `draft` `issued` `reserved` `redeemed` `void` — สิ่งที่คนกระทำ |
| `reservedUntil` | จองไว้ถึงเมื่อไหร่ (เลยเวลาแล้วปล่อยเอง) |
| `redeemedAt` | ใช้เมื่อไหร่ |
| `redeemedBy` | พนักงาน/สาขาที่ตัดสิทธิ์ |

**สถานะที่ผู้ใช้เห็นไม่ได้เก็บลงฐานข้อมูล** แต่คำนวณสดจาก `deriveStatus()`
→ อ่าน [01 ระบบคิดยังไง](01-ระบบคิดยังไง.md) หัวข้อ 2

### หน้าตา · `design`

| field | ค่าเริ่มต้น | อธิบาย |
|---|---|---|
| `skin` | `'steel'` | ธีม — `steel` `ink` `voltage` |
| `layout` | `'slab'` | รูปแบบ — `slab` `strip` `mini` |
| `accent` | `null` | ทับสีเน้นเฉพาะใบนี้ เช่น `'#1e88e5'` |
| `badge` | `null` | คำบนป้ายมุม เช่น `'PARTNER'` |
| `artUrl` | `null` | ภาพประกอบ (ยังไม่ได้ใช้ — เผื่อไว้) |

`design` **ไม่มีผลกับตรรกะเลย** ลบทิ้งทั้งก้อนคูปองก็ยังคิดเงินถูก

## บริบทตอนใช้สิทธิ์

อีกครึ่งของสมการ — ส่งเข้า `evaluate()` / `check()` / `redeem()`

```js
{
  now: Date.now(),          // เวลาอ้างอิง (ใส่เองได้เพื่อทดสอบ)
  orderTotal: 24000,        // ยอดก่อนลด
  items: [                  // ใส่เมื่อคูปองจำกัดสินค้า
    { sku: 'KN-TW-12', category: 'stair', price: 2000, qty: 2 },
  ],
  customerId: 'cus_1029',
  segments: ['partner'],    // กลุ่มที่ลูกค้าคนนี้เป็นอยู่
  channel: 'web',
  branch: 'สาขาบางนา',
  hasOtherDiscount: false,
}
```

ผลที่ได้กลับ:

```js
{
  ok: true,
  reasons: [],       // ถ้าใช้ไม่ได้ reasons[0] คือข้อที่ควรโชว์
  status: 'active',
  base: 24000,       // ยอดที่คูปองมีสิทธิ์ลด
  discount: 2000,
  payable: 22000,
  freeShipping: false,
  freeItems: 0,
}
```

`reasons` ใช้คีย์เดียวกับ `strings.th.js` หัวข้อ `reject.*` เอาไปโชว์ได้เลย:

```js
t(`reject.${primaryReason(result.reasons)}`)   // "ยอดซื้อยังไม่ถึงขั้นต่ำ"
```

รายการเหตุผลทั้งหมด: `bad_code` `not_found` `voided` `already_redeemed` `expired`
`not_started` `reserved` `wrong_customer` `segment` `limit_total` `limit_per_person`
`channel` `branch` `product_scope` `min_spend` `not_combinable`

## รหัสคูปอง

รูปแบบ `PREFIX-XXXX-XXXC`

- `PREFIX` — อักษรนำหน้าของแคมเปญ 2-4 ตัว (เช่น `SPE` `VIP` `SHIP`)
- `X` — ตัวสุ่ม
- `C` — **ตัวตรวจทาน** ตัวสุดท้าย

ชุดตัวอักษรใช้ Crockford Base32: `0123456789ABCDEFGHJKMNPQRSTVWXYZ`
ตัด `I` `L` `O` `U` ทิ้ง — เพราะคนอ่านสลับกับ `1` `0` และกันคำหยาบโผล่โดยบังเอิญ
ถ้าใครพิมพ์ตัวที่ตัดทิ้งมา ระบบซ่อมให้เอง (`O→0`, `I/L→1`, `U→V`)

**ตัวตรวจทานทำอะไร** — จับพิมพ์ผิด 1 ตัวได้ 100% และจับสลับตัวติดกันได้เกิน 90%
ระบบจึงตอบว่า *"รหัสไม่ถูกต้อง พิมพ์ตกหรือเกินหรือเปล่า"* แทนที่จะบอกว่า *"ไม่พบคูปอง"*
ซึ่งเป็นคนละเรื่องกันในสายตาพนักงาน

> ⚠️ ตัวตรวจทาน **ไม่ใช่ระบบความปลอดภัย** มันแค่กันพิมพ์ผิด
> ความปลอดภัยจริงมาจากความสุ่ม (32⁷ ≈ 3.4 หมื่นล้านชุด) + หลังบ้านเป็นคนตัดสิน

## ตรวจข้อมูลก่อนใช้

```js
import { createVoucher, validateVoucher } from './src/index.js';

const v = createVoucher(ข้อมูลจากที่ไหนก็ตาม);
const problems = validateVoucher(v);   // [] = ผ่าน
```

จับได้เช่น ส่วนลดเกิน 100% · วันเริ่มหลังวันหมด · `kind` ที่ไม่รู้จัก · ธีมที่ไม่มีอยู่จริง

**เรียกทุกครั้งที่รับข้อมูลจากภายนอก** (ไฟล์ JSON · API · ฟอร์ม)
ชุดทดสอบมีข้อหนึ่งที่ตรวจไฟล์ตัวอย่างในโปรเจกต์ด้วย เพราะเคยพลาดมาแล้ว —
รหัสที่พิมพ์เองไม่ผ่านตัวตรวจทาน ทำให้เปิดหน้าคูปองไม่ได้สักใบทั้งที่หน้ารายการดูปกติดี
