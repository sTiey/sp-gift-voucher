# 05 · ความปลอดภัยและกับดัก

หน้านี้พูดตรง ๆ ว่า **อะไรที่ยังไม่ปลอดภัย** และ **กับดักที่รู้อยู่แล้วว่ามี**

---

## 1. ข้อจำกัดใหญ่ที่สุด: หน้าเว็บเป็นคนตัดสิน

ตอนนี้ทุกอย่างเกิดในเบราว์เซอร์ ตั้งแต่ตรวจว่าคูปองใช้ได้ไหม ไปจนถึงตัดสิทธิ์

**แปลว่าอะไร** — ใครก็ตามที่เปิดเครื่องมือนักพัฒนาในเบราว์เซอร์ตัวเอง
สามารถแก้ตัวเลขส่วนลด หรือทำให้คูปองที่ใช้ไปแล้วกลับมาใช้ได้อีก

**ใช้แบบนี้ได้กับ** — สาธิตให้ดู · ต้นแบบทดลอง · ให้ทีมเล่นเพื่อเคาะหน้าตา

**ใช้แบบนี้ไม่ได้กับ** — เงินจริง ลูกค้าจริง

**ทางแก้** — ย้าย `check` / `reserve` / `redeem` ไปที่เซิร์ฟเวอร์
โฟลเดอร์ `src/core/` ออกแบบมาให้ก๊อปไปวางบน Node.js ได้ทั้งก้อนอยู่แล้ว
หน้าเว็บเหลือหน้าที่แค่ "ถามแล้วเอาคำตอบมาแสดง"

---

## 2. รหัสยืนยันสด — ทำไมต้องมี และตอนนี้ยังไม่พอ

**ปัญหาจริง** ลูกค้าแคปหน้าจอคูปองส่งให้เพื่อน เพื่อนเอาไปใช้ที่ร้าน
พนักงานมองด้วยตาแยกไม่ออกว่าเป็นภาพหน้าจอหรือของจริง

**ทางแก้ที่ร้านค้าทั่วโลกใช้** โชว์ตัวเลข 4 หลักที่เปลี่ยนเองทุก 30 วินาที
พนักงานเทียบกับเลขบนเครื่องตัวเอง ภาพหน้าจอที่ถ่ายไว้เมื่อกี้จะได้เลขไม่ตรงทันที

**ที่ทำไว้ตอนนี้** คิดเลขในเบราว์เซอร์จากความลับที่ฝังอยู่ในหน้าเว็บ
→ เดินได้จริง เห็นภาพได้ แต่ **ปลอมได้ถ้าตั้งใจ**

**ของจริงต้องเป็น**

```
เซิร์ฟเวอร์:  code = HMAC-SHA256(ความลับ, voucherId + ช่วงเวลา) → เอา 4 หลัก
หน้าเว็บ:     ขอเลขจากเซิร์ฟเวอร์มาโชว์เฉย ๆ ไม่ต้องรู้ความลับ
เครื่องพนักงาน: ขอเลขของคูปองใบเดียวกันจากเซิร์ฟเวอร์ แล้วเทียบ
```

ความลับต้องอยู่บนเซิร์ฟเวอร์เท่านั้น · แก้ที่ `src/core/security.js`

## 3. รหัสคูปองเดาได้ไหม

ตัวรหัสมี 7 ตัวสุ่มจากชุด 32 ตัวอักษร = **34,359,738,368 ชุด** (สามหมื่นสี่พันล้าน)
สุ่มยิงมั่วมีโอกาสถูก 1 ใน 34 พันล้านต่อครั้ง

**แต่** ถ้าไม่จำกัดจำนวนครั้งที่ยิงตรวจได้ คนที่ตั้งใจก็ยิงวันละล้านครั้งได้

**ต้องทำ** จำกัดจำนวนครั้งต่อ IP ต่อนาที และล็อกชั่วคราวเมื่อผิดติดกันหลายครั้ง
ทำที่เซิร์ฟเวอร์ ไม่ใช่ที่หน้าเว็บ

> ตัวตรวจทานท้ายรหัส **ไม่ได้ช่วยเรื่องความปลอดภัย** มันแค่กันพิมพ์ผิด
> จริง ๆ แล้วมันลดพื้นที่สุ่มลง 32 เท่าด้วยซ้ำ แต่แลกมากับประสบการณ์ที่ดีขึ้นมาก
> ตอนพนักงานพิมพ์รหัส — คุ้มกว่า

---

## 4. คูปองที่ผูกกับลูกค้าคนเดียว

ตั้ง `audience.customerId` แล้วคนอื่นใช้ไม่ได้ — **แต่ต้องส่ง `customerId` มาตอนตรวจด้วย**
ถ้าไม่ส่งมา ระบบตรวจไม่ได้ว่าเป็นคนเดียวกันหรือเปล่า และจะปล่อยผ่าน

เรื่องเดียวกันกับ `limits.perPerson` — นับจาก `usage.byCustomer` ถ้าไม่ส่งไอดีมา
ก็นับไม่ได้ ชุดทดสอบมีข้อที่ยืนยันพฤติกรรมนี้ไว้ชัด ๆ เพื่อไม่ให้ใครเข้าใจผิด

**สรุป: ระบบหลังบ้านต้องรู้ว่ากำลังคุยกับลูกค้าคนไหนเสมอ**

## 5. กับดักเรื่องหน้าจอมือถือ

### 5.1 `position: fixed` บน iPhone

Safari บน iPhone มีพฤติกรรมที่ทำให้คนแก้กันหลายรอบ:

1. **`fixed` วาดไม่ถึงก้นจอ** ไม่ว่าจะสั่งความสูงเท่าไหร่ → เกิดแถบดำใต้จอ
2. **`fixed` ที่อยู่ในกล่องที่ตัดขอบ** (`overflow: clip/hidden`) → iOS หยุดวาดทั้งกล่อง

**ระบบนี้จึงเลี่ยง `fixed` ตั้งแต่ต้น**
- แถบหัวเรื่องใช้ `sticky` ไม่ใช่ `fixed`
- หน้าใช้สิทธิ์ไม่มีแผงเลื่อนขึ้นจากล่างจอ — ใบคูปองฉีกอยู่กับที่แล้วรหัสขึ้นในหน้าเลย
  (ตัดปัญหาทิ้งไปเลย และใช้งานง่ายกว่าด้วย เพราะไม่ต้องปิดแผงอะไร)
- มีแค่ข้อความแจ้งชั่วคราวมุมล่างที่ใช้ `fixed` ซึ่งเป็นของชั่วคราวไม่กินพื้นที่

> ⚠️ **เครื่องคอมมองไม่เห็นบั๊กพวกนี้เด็ดขาด** ต้องเปิดบน iPhone จริงเท่านั้น
> ระบบนี้ยังไม่มีใครทดสอบบนมือถือจริงเลยสักครั้ง

### 5.2 ระยะปลอดภัยขอบจอ

มีโทเคน `--vk-safe-top` / `--vk-safe-bottom` อ่านจาก `env(safe-area-inset-*)`
ต้องคู่กับ `viewport-fit=cover` ในแท็ก viewport ซึ่งใส่ไว้ให้แล้วทุกหน้า

## 6. กับดักที่เจอระหว่างสร้าง (จดไว้กันพลาดซ้ำ)

| อาการ | ต้นตอจริง | บทเรียน |
|---|---|---|
| การ์ดแบนหมดทั้งใบ ตัวเลขเล็กเท่าตัวหนังสือธรรมดา | `clamp()` ผสมตัวเลขเปล่ากับความยาว → ค่าเสียทั้งก้อน | **CSS ที่ค่าเสียไม่ error** มันแค่ตกกลับไปใช้ค่าเริ่มต้นเงียบ ๆ |
| QR วาดออกมาสวยแต่สแกนไม่ออก | พหุนามกันพัง Reed-Solomon สลับพจน์ | รูปดูปกติทุกอย่าง ต้องเทียบกับตัวมาตรฐานถึงจะรู้ |
| หน้ารายการโชว์คูปองครบ แต่กดเข้าไปขึ้น "รหัสไม่ถูกต้อง" ทุกใบ | รหัสในไฟล์ตัวอย่างพิมพ์เอง ไม่ผ่านตัวตรวจทาน | **ข้อมูลตัวอย่างต้องผ่านตัวตรวจเหมือนข้อมูลจริง** |
| พนักงานพิมพ์ `ship4c7b8xjr` ติดกันแล้วหาไม่เจอ | ตัว `I` ใน prefix "SHIP" โดนซ่อมเป็นเลข 1 | ต้องแยก prefix ออกก่อนแล้วค่อยซ่อมเฉพาะตัวรหัส |
| โค้ดสาธารณะตายหลังคนแรกใช้ | `limits.total = null` ถูกตีความว่า "ปิดใบทันที" | ต้องแยกให้ชัดว่า `null` แปลว่าไม่จำกัด |
| ชิปเล็กซ้อนทับกันจนอ่านไม่ออก | กล่องที่ตั้ง `container-type: inline-size` ใส่ `width: fit-content` แล้วยุบเป็นศูนย์ | container query วัดตัวเองไม่ได้ |
| วรรณยุกต์ไทยชนบรรทัดบน | `line-height: 1` | ไทยซ้อนสระ/วรรณยุกต์ได้ 2 ชั้น ต่ำกว่า ~1.1 ไม่ได้ |

**สิ่งที่เหมือนกันทุกข้อ: ไม่มี error สักตัว** หน้าเว็บยังทำงาน ยังสวย แค่ผิด
ทางเดียวที่จับได้คือ **เปิดดูของจริงแล้วเทียบกับสิ่งที่ควรจะเป็น**

## 7. ความเป็นส่วนตัว

- **QR สร้างในเครื่อง** ไม่ส่งรหัสคูปองของลูกค้าออกไปให้บริการภายนอกวาดให้
- **ฟอนต์เก็บไว้เอง** ไม่ยิงไปที่เซิร์ฟเวอร์ฟอนต์ของใคร (ซึ่งจะเห็น IP ลูกค้าทุกคน)
- **ไม่มีตัวติดตามใด ๆ** ในโค้ดชุดนี้
- ตอนต่อของจริง: ระวังอย่าใส่รหัสคูปองลงใน URL ที่ถูกเก็บ log ทั้งเส้นทาง
